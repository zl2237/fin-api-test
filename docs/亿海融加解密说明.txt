##### 一、对接地址

亿海融企业信息查询接口的对接地址以对方实际提供为准（测试/生产分开）。

注：
平台「环境管理」中为亿海融建对应环境并录入 base_url；
密钥配置在「环境编辑 → 加密配置」，接口侧按名称引用。

##### 二、密钥使用规则

请求方（我方）生成 RSA 密钥对：公钥交亿海融（他们用它加密回包），
私钥自己留存（请求签名 + 响应解密都用它）。

生产和测试环境禁止共用一套密钥。

平台录入格式：
公钥 X.509/SPKI（-----BEGIN PUBLIC KEY----- 开头，粘贴裸 Base64 亦可）；
私钥 PKCS#8 无口令（-----BEGIN PRIVATE KEY----- 开头）。

##### 三、通信约定

请求方式：POST，Content-Type application/json，字符编码 UTF-8
签名算法：RSA + MD5（PHP 常量 OPENSSL_ALGO_MD5，即 MD5withRSA / PKCS1v15）
RSA 填充方式：OPENSSL_PKCS1_PADDING

请求体两个字段：
data —— 统一社会信用代码字符串列表先 JSON 编码再 Base64（不进行 RSA 加密），
       列表最多 200 项
sign —— 用请求方私钥对 data 的原始字符串（Base64 文本本身）做 RSA-MD5
       签名，签名结果 Base64

服务端用请求方公钥验签。失败码 501~507（缺参/坏 Base64/坏 JSON/空列表/
超限/信用代码格式错/验签失败），成功 code=200。

响应 data：企业信息 JSON 用请求方公钥分段加密，逐段密文按原顺序拼接后
整体一次 Base64。分段大小按 RSA 密钥长度及 PKCS#1 v1.5 填充限制：
2048 位密钥单段明文最大 245 字节，1024 位为 117 字节（模长 - 11）。
失败响应（code=5xx）data 为空字符串，明文 JSON，不加密。

解析：data 先 Base64 解码，再按密钥字节长度（key_size/8，2048 位=256、
1024 位=128）拆分密文块，私钥逐段解密、按顺序拼接明文，最后 JSON 解码。
未查询到数据的信用代码对应空列表 []。

##### 四、平台配置步骤

1. 环境编辑 → 加密配置：添加密钥对（名称如 yhr），录入公钥 + 私钥，
   保存后点「测试加解密」自检——自检按密钥位数自适应分段，文案会显示
   实际位数（1024/2048 位均可通过）。
2. 接口编辑 → 请求字段：添加字段 key=credit_codes，类型 array，
   示例值为 JSON 数组（如 ["91330100MA2B23"]）。
   说明：平台字段体系无法表达根节点为字符串数组的请求体，信用代码列表
   存于该字段，由签名模式按取值字段提取。
3. 接口编辑 → 加密配置：
   请求侧开启，模式选「参数签名」，密钥对名称 yhr，
   数据字段 data、签名字段 sign（按协议默认，可改），
   取值字段 credit_codes（留空 = 整个请求体作为载荷）。
4. 响应侧开启「响应解密」：密钥对名称 yhr，解密模式「包裹字段」，
   密文字段 data。失败响应（code=5xx）自动走业务码判定可见。
5. 调试弹窗「实际发出报文」展示完整 {data, sign} 信封，可核对签名。

##### 五、与海关 requestCipher 协议的差异

海关协议：整个请求体 JSON 用对方公钥分段 RSA 加密，包成
{requestCipher: 密文} 信封；响应当前为明文。
亿海融协议：请求 data 不加密（仅 JSON+Base64），另加私钥 MD5withRSA
签名字段；响应用我方公钥分段加密，需要解密。
关键区别：海关模式用「公钥」加密请求，亿海融签名用「私钥」签请求——
同一密钥对里两者都要录全。

##### 六、实现注记

1. 分段/块长全部按密钥位数自适应（不写死 2048）：短钥匙配大段长时
   平台会报中文错误（含密钥位数与该钥上限），不再出现英文
   "Encryption failed"。
2. 签名覆盖的是自己放进 data 的 Base64 文本，PHP json_encode 与
   Python json.dumps 的序列化差异（斜杠转义 \/、非 ASCII 转 \uXXXX）
   不影响验签；统一社会信用代码为纯字母数字，两种序列化字节一致。
3. PKCS1v15 签名无随机填充：同钥同文必得同签（确定性），便于比对排障；
   协议本身无时间戳/防重放设计，重发安全。
4. 信用代码格式/数量（≤200）预校验不在平台侧做，由服务端 504/505/506
   兜底。

##### 附：状态码

200 success 成功
501 missing parameter 缺少 data 或 sign 参数
502 invalid base64 data data 不是有效 Base64
503 invalid data format data 解码后不是合法 JSON 字符串列表
504 empty credit code list 列表为空
505 credit code list exceeds limit 数量超过 200
506 invalid credit code 信用代码格式不正确
507 signature verification failed sign 格式错误或验签失败
500 internal server error 服务端内部异常
