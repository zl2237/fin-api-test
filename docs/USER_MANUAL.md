## 1. 平台是做什么的

一句话：**把"调用一串接口、验证每步结果"的重复劳动，变成在网页上拖一拖、点一点**。

传统的接口自动化要写脚本：发请求、取返回值、拼下一个请求、断言结果……平台把这些全部可视化了：

- 接口像积木一样在画布上摆成一条流程线（先登录 → 再下单 → 再查订单 → 最后核销）；
- 每个接口要发什么数据，在数据集页面像填表格一样配置；
- 点一下执行，平台按顺序自动跑完整条流程，逐步给出请求、响应和断言结果；
- 跑挂了不用从头再来，可以从失败的那一步"断点续跑"。

## 2. 五个核心概念

用"做一桌菜"来打比方：

| 概念 | 是什么 | 比喻 | 菜单位置 |
|---|---|---|---|
| **项目** | 一个业务线的"文件夹"，接口、用例都挂在项目下 | 厨房分区 | 项目管理 |
| **接口** | 平台对被测系统一个接口的登记（地址、方法、有哪些字段、示例值） | 菜谱 | 接口管理 |
| **用例** | 画布上把多个接口连成的一条流程线 | 套餐（菜谱的组合） | 用例管理 |
| **数据集** | 用例里每个节点的实际"用料表"——每个参数发什么值 | 每道菜的实际配料 | 数据集 |
| **环境** | 被测系统的地址、账号、数据库连接等 | 厨房（在哪做这桌菜） | 环境配置 |

一条完整的链路：**项目里登记接口 → 用例画布把接口连成流程 → 数据集给每个节点配数据 → 选个环境执行 → 看报告**。

## 3. 十分钟上手：跑通第一条用例

### 第 1 步：登录

打开平台地址，输入账号密码。第一次登录会强制要求改密码，改完重新登录即可。

### 第 2 步：建项目

左侧菜单 **资源配置 → 项目管理** → 新建。名字随意（比如"财务中台"）。项目只是容器，后面所有东西都挂在它下面。

### 第 3 步：配环境

**资源配置 → 环境配置** → 新建：

- **基础地址**：被测服务的域名，比如 `https://fin-tidb.example.com`（接口里只写路径部分，执行时自动拼上）；
- **公共请求头**：比如登录 token、Content-Type——所有请求都会自动带上；
- **数据库连接**：如果要用"查数据库取值"这种动态参数，这里要配好被测库的连接；
- **成功状态码**：哪些 HTTP 状态码算请求成功（一般默认 200 就够）。

测试环境、预发环境各建一套，执行时选一套即可。

### 第 4 步：登记接口

**测试工作台 → 接口管理** → 新建（或选中分组后新建）。三种录入方式：

1. **手动填**：方法 + 路径 + 名称；
2. **cURL 导入**（推荐）：在浏览器/Postman 里把请求复制成 cURL 命令，粘进导入框，地址、请求头、请求体一次性带进来；
3. **JSON 导入**：直接粘贴请求体 JSON。

进编辑页后重点填两块：

- **字段表**：这个接口的请求体有哪些字段（名字、类型、示例值）。示例值非常重要——新建数据集时平台会按它给你预填参数；
- **请求头模板**：这个接口特有的请求头（会与环境公共头合并）。

### 第 5 步：编排用例

**测试工作台 → 用例管理** → 新建用例，进入编排画布：

1. 从左侧接口列表**点击**接口，画布上出现一个节点；
2. 鼠标悬停节点边缘出现连接点，**从上一个节点拖到下一个节点**连线（连线代表先后依赖）；
3. **双击节点**（或选中后按 Enter）打开右侧配置抽屉；
4. **Ctrl+S 保存**——保存时平台会自动为这条用例生成一份配套数据集，每个节点一份初始参数表，不用自己建。

### 第 6 步：配数据

**测试工作台 → 数据集** → 找到刚才自动生成的数据集 → 点节点进去，看到一张参数表：每一行是一个参数，右侧下拉选它的**取值方式**（固定值 / 引用 / 函数 / 查库，详见 [4.3 数据集](#43-数据集重点)）。

新手建议：先把所有参数都用"固定值"跑通一遍，再逐个换成动态取值。

### 第 7 步：执行并看报告

回到用例列表，点行内的**执行**按钮，选环境。跑完后自动跳到报告页：

- 顶部是总结论（通过 x / 共 y）；
- 往下每一步：发出的请求、收到的响应、断言结果、提取到的变量，全都能展开看；
- 右上角可**导出** CSV（Excel 能开）或 HTML（自包含单文件，可直接发给别人）。

## 4. 功能详解

左侧菜单分三组：**测试工作台**（日常高频）、**资源配置**（建一次用很久）、**系统管理**（仅管理员可见）。

### 4.1 接口管理

**列表页**

- 左侧分组树：可多级分组、拖动接口换组、批量移动；
- 顶部搜索：按名称/路径模糊搜，拼音也行；
- 导出：Excel 表格，给团队传阅接口清单很方便。

**编辑页**

- **字段与示例值**：字段类型（string/number/array/object/file…）决定了数据集里这个参数长什么样。示例值的作用有两个：新数据集初始化时预填参数、数组字段按示例值首元素的结构当作元素模板；
- **cURL 导入**：随时可以把一个真实请求贴进来生成/更新接口；
- **契约同步弹窗**：当你**修改字段后保存**，平台会弹窗提醒"这次改动影响了哪些用例的数据集"——列表里能看到每个受影响节点缺了哪些字段、多了哪些参数。点确认同步，平台会把缺的字段补进数据集（固定值形式）。
  **放心点**：你配的引用/函数/查库这类动态参数，平台一个都不会动，只会在统计里提示"跳过"。

### 4.2 用例管理与编排

**用例列表**

- 勾选多行 → **批量执行**（可调并发数，一起跑）；
- 勾选多行 → 按 **Ctrl+Enter** 快速执行选中的第一条；
- **定时任务**：给用例设个周期（比如每天早上 8 点），到点自动执行，结果进执行记录；
- **数据驱动**：数据集配了多行数据时，一次执行会自动一行数据跑一遍流程，产出多份报告。

**编排画布**

| 操作 | 方式 |
|---|---|
| 添加节点 | 点击左侧接口 |
| 连线（依赖） | 从节点边缘连接点拖到目标节点 |
| 打开配置 | 双击节点，或选中后 Enter |
| 删除节点 | 选中后 Delete |
| 复制/粘贴节点 | Ctrl+C / Ctrl+V（粘贴出新节点，配置一并克隆） |
| 删除连线 | 双击连线 |
| 保存 | Ctrl+S |

**节点配置抽屉**里有四块：

1. **参数表**：这个节点每个参数怎么取值（和 4.3 数据集是同一张表，改哪边都行）；
2. **断言**：怎么判定这步算通过。常用的是 JSONPath 取响应里的值做比较，比如 `$.code` 等于 `200`、`$.data.order_no` 不为空。支持多行断言，全部满足才算过；
3. **后置提取**：从响应里"摘"值存成变量，给后面的节点用。比如提取 `$.data.token` 存为 `token`；
4. **重试与等待**：失败自动重试几次、节点执行前等多少毫秒（对付异步落库的场景很有用）。

### 4.3 数据集（重点）

**为什么要有数据集**：用例画布只负责"流程长什么样"（骨架），数据集负责"每一步发什么"（血肉）。骨架与血肉分离，同一套流程可以配多份数据跑出不同场景。

**参数的四种取值方式**——平台最核心的设计，务必搞懂：

| 方式 | 意思 | 什么时候用 | 例子 |
|---|---|---|---|
| **固定值** | 写死什么就发什么 | 不变的参数（币种、类型码） | `"CNY"` |
| **引用** | 拿流程里**别的节点**产生的值 | 前面步骤的返回值后面要用 | 引用"新建订单"节点提取的 `order_id` |
| **函数** | 平台现场算一个 | 要唯一/随机的值 | 随机手机号、时间戳、唯一 ID |
| **查库** | 到数据库里现查一条 | 要"真实存在的最新数据" | `SELECT id FROM orders WHERE ... LIMIT 1` |

- 引用和查库都能形成"依赖链"：比如"查库"参数的 SQL 里写了 `{{某节点.order_id}}`，平台会自动先解析被依赖的参数再执行这条 SQL，你不用操心先后顺序；
- SQL 里引用别的节点变量统一写 `{{节点ID.变量名}}`，双花括号；
- 数组参数按下标写路径：`statement.0.receive_id` 表示"statement 数组第 1 个元素里的 receive_id"。

**契约黄条**：数据集页和报告页偶尔会出现一条黄色提示，说某节点"缺少字段/多余参数"。意思是**接口定义的字段表**和**数据集实际配的参数**对不上：

- 点提示里的同步按钮，缺的会用"固定值"补上；
- 多出来的固定值参数会帮你删掉；
- **动态参数（引用/函数/查库）永远不会被动**——这是平台的硬规则。

黄条只是提醒不是报错，执行不受影响。补不补看你业务上需不需要那个字段。

**多行数据驱动**：一个数据集可以加多行数据（比如正常单、金额为 0 的单、超长备注的单），执行时每行各跑一遍完整流程。

### 4.4 执行与报告

**执行记录页**：所有执行历史，按状态/用例/时间筛选，附近 N 天趋势统计。

**报告详情页**——排障三板斧：

1. **看断言**：失败步骤展开，红色断言会显示"期望值 vs 实际值"，一眼看出差在哪；
2. **编辑并重放**：点请求体旁的"编辑并重放…"，直接改请求参数原地重发一次（不写回报告、不动数据集），用来快速验证"改成什么才能过"。调通了会挂"已重放通过"徽标；
3. **断点续跑**：确认正确参数后，把它同步进数据集，然后点报告页的"断点续跑"——从**第一个失败节点**重新开始，前面成功的步骤不重跑，结果覆盖本记录。这对"跑 30 步挂在第 28 步"的长流程是救命功能。

> 提醒：**重放通过 ≠ 用例通过**。重放只是验证参数方向对，一定要把参数落到数据集再断点续跑，用例才算真正修复。

报告还能看：每步的提取变量、耗时、重试次数；顶部的契约出入黄条（同 4.3）；右上角导出 CSV/HTML。

### 4.5 套件编排

单条用例是"一道流程"，套件是"一整场回归"：把多条用例（或多条流程）按顺序串起来一次跑完，适合版本回归、冒烟。入口在用例列表新建套件，报告在套件报告页看总览 + 各成员明细。

### 4.6 项目管理与环境配置

- **项目管理**：项目的增删改，以及**项目版本**历史（接口/用例的历史版本可追溯）；
- **环境配置**：见第 3 节第 3 步。要点：公共请求头全请求生效；数据库连接是"查库"参数的前提；多环境之间互不影响。

### 4.7 字段字典与文件中心

- **字段字典**：把业务上反复出现的枚举值（费用类型、单据状态等）维护成字典，配参数时从下拉里选，不用每次手敲，也避免拼写不一致；
- **文件中心**：上传测试要用的文件（发票图片、附件），接口字段类型选 `file` 后，在数据集里直接从文件中心挑选。

### 4.8 系统管理（仅管理员）

- **用户管理**：账号增删、角色分配（普通用户/管理员）、强制改密标记；
- **操作日志**：谁在什么时间改了什么（含契约同步这类批量操作），审计用。

## 5. 效率技巧与快捷键

| 快捷键 | 位置 | 作用 |
|---|---|---|
| **Ctrl+K**（Mac: Cmd+K） | 全局 | 命令面板：搜接口/用例/数据集/报告，直达页面 |
| **Ctrl+S** | 接口编辑/用例编排/环境编辑 | 保存 |
| **Ctrl+Enter** | 用例列表 | 执行勾选的用例 |
| **Ctrl+C / Ctrl+V** | 编排画布 | 复制/粘贴节点（含配置） |
| **Delete** | 编排画布 | 删除选中节点 |
| **双击连线** | 编排画布 | 删除该连线 |

其他技巧：

- 报告页请求/响应 JSON 可一键复制（平台已处理成合法 JSON，不会复制出奇怪格式）；
- 用例可以直接复制一份再改，快速做场景变体；
- 浏览器标签页的图标与标题会实时反映执行状态，切去干别的事，跑完扫一眼标签就知道过没过。

## 6. 常见问题 FAQ

**Q1：报告/数据集出现黄色"契约出入"提示，必须处理吗？**
不是必须。它表示接口字段表和数据集参数对不上，执行照常。想对齐就点同步（缺的补固定值、多的固定值删除、动态参数不动）。注意：同步是"接口维度"的——会把所有引用该接口的数据集一起同步。

**Q2：我配的动态参数（引用/函数/查库）会被契约同步改掉吗？**
不会。这是平台红线：非"固定值"来源的参数在任何同步操作中都只统计、不修改、不删除。

**Q3：断点续跑和重新执行有什么区别？**
重新执行=整条流程从头跑；断点续跑=从第一个失败节点接着跑，成功的步骤不重复（避免重复下单之类的副作用）。续跑用的是**当前最新的数据集配置**，所以"改数据集 → 续跑"是最常用的修用例姿势。

**Q4：重放显示通过了，用例算修好了吗？**
不算。重放只是用改过的请求体验证一次，不落任何配置。要修好：把正确参数写进数据集 → 断点续跑 → 报告变绿才算数。

**Q5：数组参数怎么配？**
按"路径.下标.字段"逐项配，如 `statement.0.amount`。数组的结构模板来自接口示例值的首元素——所以接口的字段示例值要尽量填完整、填真实。

**Q6：查库参数里怎么用别的节点的值？**
SQL 里写占位符 `{{节点ID.变量名}}`，比如 `SELECT id FROM orders WHERE bl_no = {{n_create.bl_no}} LIMIT 1`。平台会自动按依赖顺序先解析 `n_create.bl_no` 再执行这条 SQL。

**Q7：一个参数每次执行都要用"当次产生的数据"（比如刚创建的订单号），怎么配？**
三步：上游节点配**后置提取**把订单号摘成变量 → 下游参数选**引用**指向它 → 一定要引用/提取，不要写死。写死的值在下次执行时会指向旧数据，是长流程用例最常见的翻车原因。

**Q8：想给用例每天定时跑怎么办？**
用例列表 → 定时任务 → 选周期。执行结果照常进执行记录，配合环境切换可以做到"测试环境每天冒烟"。
