# 数据驱动测试 · 开发方案定案

> 状态：**已定案待开发**（六轮 grilling 钉死，2026-08-24）
> 前置调查结论：平台现状为"单实例流程驱动"——字段默认值支持 `${...}` 表达式、环境变量、节点间提取/注入（post_extract / set_field），但无"一组用例 × N 组数据"的乘积执行、数据集存储、执行时参数覆盖能力。本方案在其上补"多组数据"乘积层。

## 一、分叉定案

| # | 分叉 | 定案 | 否决项及原因 |
|---|---|---|---|
| 1 | 是否开发 | ✅ 立项 | — |
| 2 | 存储形态 | 内建数据集表，**项目级共享**（可被多用例引用） | 纯文件驱动（列名拼写错只能执行时发现，列定义无法复用）；DB 查询驱动（测试数据与业务数据耦合） |
| 3 | 执行模型 | **每行一条执行记录** | 一条记录 N 轮（StepRecord 加 iteration，报告/通知/执行器全要改循环，改动面大风险高） |
| 4 | 注入机制 | **列名即变量名**：行值直接写入变量池，**优先于同名环境变量**，`${列名}` 在字段默认值/前置处理/断言中直接引用 | 用例侧映射表（每用例多配一层，上手门槛高） |
| 5 | 绑定入口 | **用例级绑定**：TestCase 加可空 `dataset_id`；手动/批量/定时统一自动逐行跑 | 执行时临时选（定时任务拿不到数据集，需另加链路） |
| 6 | 数据录入 | 页面行编辑 + **Excel/CSV 导入** | 仅行编辑（多行数据手录痛苦） |
| 7 | 失败通知 | 数据驱动**批量执行失败只发一条汇总**（含失败行号列表）；单行手动执行保持逐条 | 逐行各发（N 行全挂刷屏 N 条） |

## 二、数据层设计

### 新表

```
data_sets        数据集（项目级）
  id, project_id, name, description,
  columns        JSON  # 列定义 [{"key": "bl_no", "label": "运单号", "type": "string"}]
  created_by/updated_by/created_at/updated_at

data_set_rows    数据行
  id, dataset_id, row_index,      # row_index 维护行序（1 起）
  data          JSON              # {"bl_no": "BL001", "put_amount": 100}
  created_at
```

- 删除数据集级联删行；被用例引用的数据集删除时**拒绝**（提示先解绑），防用例空绑定。
- 项目删除级联（与现有一致）。

### 既有表变更

```
test_cases         + dataset_id  INT NULL  # 绑定的数据集，NULL = 普通用例
execution_records  + dataset_id  INT NULL  # 执行时实际使用的数据集（快照解耦：数据集后续改行不影响历史记录）
                    + dataset_row JSON NULL # 该次执行对应的数据行 {row_index, data, label}
```

- alembic 迁移一份（两表加列 + 两新表）。

## 三、执行链路（改动最小化原则）

### 变量注入

- `ExecutionContext(env_vars=env.variables)` 初始化处合并：**变量池初始值 = env.variables 被数据行覆盖同名项**。
- 行值进池后，现有表达式引擎（`${bl_no}` / `${context.bl_no}`）零改动直接可用；字段默认值、pre_process、断言、headers 全链路生效。
- 行值不做类型转换，一律按列定义的 `type` 在 body_builder 既有强转逻辑里处理（string/int/bool/array/object 复用 `parse_field_value` 路径）。

### 执行展开

- 用例绑定数据集且数据集有 N 行 → 单击执行展开为 N 次执行，**复用 `create_executions_batch` + `submit_batch_execution`**（并发上限 4、共享登录 token 防互踢全部免费复用）。
- 每条记录落 `dataset_id + dataset_row` 快照（失败可溯源是哪行数据）。
- 数据集 0 行 → 拒绝执行（400，提示先录入数据）；未绑定 → 行为与现状完全一致。
- 定时任务：scheduler 触发时按绑定同样展开，免费获得数据驱动能力。

### 通知（分叉 #7）

- 批量数据驱动执行：失败结果聚合，**一条汇总通知**（用例名 + 数据集名 + 失败行号列表 + 首个失败原因），成功不发（沿用 enable_on_success 开关）。
- 单行手动执行（执行面板选了具体行）：保持逐条通知。
- 实现挂点：batch 数据驱动路径在 submit 前标记聚合标志，通知侧按标志聚合。

## 四、API 设计

```
/api/datasets                     POST 建数据集（含 columns） / GET 列表（?project_id）
/api/datasets/{id}                GET 详情（含行）/ PUT 改名改列 / DELETE（被引用拒 400）
/api/datasets/{id}/rows           POST 增行 / PUT 批量保存行序与内容 / DELETE 全清
/api/datasets/{id}/rows/{row_id}  PUT 改单行 / DELETE 删行
/api/datasets/{id}/import         POST Excel/CSV 导入（multipart；首行表头映射列 key；可選 preview）
/api/testcases/{id}               既有 PUT 扩展接受 dataset_id 字段
```

- 导入解析：openpyxl 读 xlsx；CSV UTF-8（含 BOM 兼容）；首行表头须与 columns key 匹配（多余列忽略，缺失列告警置空）。
- 审计：数据集增删改/导入均落 operation_logs。

## 五、UI 设计

1. **数据集管理页**（项目侧栏新入口，与接口管理/用例管理平级）：
   - 左：数据集列表（名称/被引用用例数/行数）；右：选中数据集的列定义编辑 + 行表格（可排序、增删行、单元格编辑）
   - 工具栏：Excel/CSV 导入（上传 → 解析预览确认 → 落库）
2. **用例绑定**：用例编辑抽屉/详情加"数据集"下拉（可选"无"），显示所选数据集行数提示
3. **执行确认**：绑定数据集的用例点执行 → 确认弹窗"N 行将执行 N 次"；执行面板可临时换数据集或仅执行部分行
4. **执行记录**：列表加"数据行"列（行号 + 首列值，如 `#3 BL00123`），报告详情顶部显示该行数据快照
5. **执行记录筛选**：按用例筛选时其数据驱动记录自然聚合展示

## 六、边界与拒绝条件

- 数据集跨项目不可绑定（用例绑定校验同项目，400）
- 用例绑定的数据集被删 → 拒绝（分叉 #2 定案的级联拒绝）
- 导入空文件/无表头 → 400
- 行数据 key 不在 columns 中 → 保存时校验拒绝（导入时缺失列置空不拒）
- dataset_row 快照不回写不更新（历史记录永远保留当次执行的真实数据）

## 七、自测计划（复用 WF-01 循环）

- **白盒单测**：变量优先级合并（行覆盖 env）、导入解析（xlsx/csv/BOM/缺列）、执行展开（N 行→N 记录、0 行拒、未绑定行为不变）、通知聚合、绑定校验拒绝路径
- **接口层**：datasets CRUD+导入全打、绑定执行展开、记录含 dataset_row、定时任务展开、跨项目绑定拒
- **UI checklist**：数据集页全量（列/行/导入/预览）、用例绑定、执行确认弹窗、记录数据行列
