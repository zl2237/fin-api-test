# 平台投产推广方案

> 场景：本周三向 2 名团队成员分享并投产 fin-api-test 接口自动化平台。
> 原则：会前有准备、会中有实操、会后有基线——一切为「独立上手 + 效能量化」服务。

## 1. 总目标与成功标准

| 层 | 目标 | 验收标准 |
|---|---|---|
| 认知 | 知道平台解决什么问题、边界在哪 | 能复述 3 个核心场景（回归/定时巡检/数据构造）与 1 个边界（不做 UI 自动化） |
| 技能 | 独立上手 | 会后 1 个工作日内，每人独立完成 1 条自己业务的真实回归用例并通过执行 |
| 共建 | 收集需求与痛点 | 结构化收集 ≥5 条，进 backlog 并给出评估排期承诺 |
| 业务 | 试点产出 | 2-4 周内 1 个核心业务流回归全量迁移到平台，形成可展示的效能对比 |

## 3. 会议流程（75 分钟）

| 时间 | 环节 | 要点 |
|---|---|---|
| 0-5 | 开场定调 | 一句话定位 + 今天你将带走什么（会跑一条用例 + 一个反馈渠道） |
| 5-10 | 痛点共识 | 用他们的日常提问：上轮回归花了多久？半夜验证怎么做的？——让他们说出痛点，而不是你讲 PPT |
| 10-30 | 真实流演示 | 按演示脚本走：HAR 导入→编排→数据集→执行→报告→企微推送；含 1 条失败用例展示定位能力（断言详情/重放/断点续跑） |
| 30-50 | 上手实操 | 每人开账号登录，跟 USER_MANUAL 第 3 节「十分钟上手」跑通演示项目的用例副本；你只答疑不代操作 |
| 50-60 | 需求与痛点收集 | 发反馈表，当场填；逐条过一遍澄清，不当场承诺实现 |
| 60-70 | 试点计划 | 宣布试点范围/周期/支持渠道/你的响应时效；约定每人迁移 1 条真实回归用例的截止日 |
| 70-75 | 收尾 | 三件事复述：账号、截止任务、反馈渠道 |

## 4. 需求与痛点：收，但结构化地收

**收什么**（三栏引导）：
1. 阻碍上手的问题（立刻修，本周内）
2. 功能缺口（进 backlog，给评估节奏：每周五批量回复）
3. 愿意用它替代的现有工作（这是效能故事的素材来源，最有价值）

**管预期**：现场只承诺「评估并反馈排期」，不承诺实现；backlog 透明可查，避免「提了没下文」流失信任。

**独立上手的抓手**：以战代练——每人从自己负责的业务里挑 1 条**已经在手工做**的回归场景迁移，目标不是学功能，是把自己的活变快。

## 5. 效能量化体系（绩效素材从 Day 1 开始积累）

### 5.1 会前先测基线（本周三之前完成，否则对比失真）

| 基线指标 | 取数方式 |
|---|---|
| 单轮核心回归手工耗时 | 问 2 人 + 自己计时，精确到人时 |
| 回归执行频率 | 现在每月几次、每次什么契机 |
| 缺陷逃逸数 | 近 3 个月上线后发现的本可被回归拦截的问题数 |
| 环境准备/测试数据构造耗时 | 单次人时 |

### 5.2 投产后持续记录（平台自带数据源）

| 指标 | 来源 |
|---|---|
| 自动化回归次数与通过率 | `/api/executions/stats`（平台现成） |
| 单轮回归平台耗时 vs 基线 | 执行记录的耗时字段 |
| 自动化用例数增长 | 用例列表计数（周环比） |
| 定时巡检拦截的问题 | 夜间/定时任务失败记录 → 转化的有效预警数 |
| 节省人时 | Σ(执行次数 × 单次节省人时)，月度汇总 |

### 5.3 月度绩效写法模板（数据 + 案例 + 趋势）

> 「投产接口自动化平台，2 名成员独立使用。核心回归从手工 4 人时/轮 → 平台 15 分钟/轮（**降幅 94%**），月回归频次 2 次 → 按需+每日巡检；累计执行 N 轮，节省约 X 人时；Y 月 Z 日上线前巡检提前发现 2 个阻断问题（案例），避免上线事故；自动化用例存量 N 条且每周净增。」

关键：**每个数字都有执行记录可溯源**，绩效表述经得起追问。
