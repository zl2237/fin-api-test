第一课：Pytest Fixtures 基础

核心概念： Fixture 是 pytest 提供的一种机制，用于为测试提供固定的数据、功能或环境。它是测试的"准备工作"。

为什么需要 Fixtures？

想象你要测试一个订单创建功能：

  • 需要先登录获取 Token
  • 需要数据库连接
  • 需要加载测试数据

如果没有 Fixtures，你需要在每个测试里重复这些代码。有了 Fixtures，只需定义一次，pytest 自动为你管理生命周期。

基础语法

1. 定义 Fixture

import pytest

# conftest.py 或测试文件中
@pytest.fixture
def login_token():
    """模拟登录，返回 Token"""
    token = "mock_token_12345"
    return token

2. 在测试中使用

def test_create_order(login_token):
    # 直接使用 fixture 提供的 token
    assert login_token == "mock_token_12345"

Fixture 的作用域

作用域 说明 使用场景
function 每个测试函数调用一次 默认值，大多数情况
class 每个测试类调用一次 测试类内共享数据
module 每个模块文件调用一次 模块级别共享（如数据库连接）
session 整个测试会话调用一次 全局配置、日志初始化

示例：模块级别的数据库连接

@pytest.fixture(scope="module")
def db_connection():
    """整个模块共享一个数据库连接"""
    conn = create_db_connection()
    yield conn  # 返回连接给测试
    conn.close()  # 测试结束后清理
yield vs return： 使用 yield 而不是 return，这样 pytest 会在测试完成后执行清理代码（teardown）。

Fixture 依赖

Fixtures 可以互相依赖！

@pytest.fixture
def db_connection():
    return create_connection()
@pytest.fixture
def order_db(db_connection):  # 依赖 db_connection
    return OrderDB(db_connection)

你的项目中的 Fixtures

查看你的 conftest.py，应该已经有类似的结构：

# conftest.py 示例结构
@pytest.fixture(scope="session")
def env_config():
    # 加载环境配置
    pass

@pytest.fixture(scope="function")
def http_client(env_config):
    # 每个测试新建一个 HTTP 客户端
    pass

小测验

如果需要为每个测试函数提供独立的订单数据，应该使用哪个作用域？

答案：function（默认值）
每个测试函数调用一次 fixture，确保测试间数据隔离。
