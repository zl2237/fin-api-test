第二课：参数化测试

核心概念： 参数化允许你用一组不同的数据重复运行同一个测试函数，而不需要写多个测试函数。

为什么需要参数化？

假设你要测试订单金额的各种情况：

  • 金额 = 0（边界值）
  • 金额 = 负数（异常值）
  • 金额 = 最大值（边界值）
  • 金额 = 正常值

没有参数化 → 写 4 个测试函数

使用参数化 → 1 个函数 + 4 组数据

基础语法

使用 @pytest.mark.parametrize

import pytest

@pytest.mark.parametrize("amount", [
    0,
    100,
    999999,
])
def test_order_amount(amount):
    # 这个测试会运行 3 次，每次使用不同的 amount
    assert amount >= 0

输出结果：

test_order_amount[0] PASSED
test_order_amount[100] PASSED
test_order_amount[999999] PASSED

多参数组合

多个参数

@pytest.mark.parametrize("currency,amount", [
    ("CNY", 100),
    ("USD", 50),
    ("EUR", 200),
])
def test_currency(currency, amount):
    assert amount > 0

笛卡尔积（多个装饰器叠加）

@pytest.mark.parametrize("currency", ["CNY", "USD"])
@pytest.mark.parametrize("amount", [100, 200])
def test_combined(currency, amount):
    # 会生成 2x2 = 4 种组合
    pass

组合结果：

test_combined[CNY-100] PASSED
test_combined[CNY-200] PASSED
test_combined[USD-100] PASSED
test_combined[USD-200] PASSED

你的项目中的应用

在你的 fin-api-test 项目中，可以这样对订单类型进行参数化测试：

@pytest.mark.parametrize("order_type", [
    "create",
    "distribute",
    "stash",
    "submit",
])
@pytest.mark.parametrize("env", ["test", "pre"])
def test_order_workflow(env, order_type):
    # 测试所有环境 × 所有订单类型组合
    pass
最佳实践： 参数化让测试覆盖更多场景，同时保持代码简洁。但不要过度使用 —— 优先测试有意义的边界值和常见场景。

从 YAML 加载数据

你的项目使用 YAML 管理测试数据，可以结合参数化：

import yaml
import pytest

# 在 conftest.py 中定义 fixture
@pytest.fixture(params=["create", "distribute"])
def order_scenarios(request):
    with open(f"data/test/order/{request.param}.yaml") as f:
        return yaml.safe_load(f)

小测验

如果我想测试 3 种支付方式和 4 种订单状态的组合，应该用几个 @pytest.mark.parametrize 装饰器？

答案：2 个装饰器（支付方式 + 订单状态），会产生 3×4 = 12 种组合。
